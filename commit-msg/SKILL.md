# commit-msg

ステージ済みの変更を読み、コミットメッセージを1つ提案する。**提案だけを行い、`git add` も `git commit` も実行しない。**

## 現在の状態（起動時に自動取得）

ブランチ:
!`git branch --show-current 2>&1 || true`

変更ファイル:
!`git status --short 2>&1 || true`

ステージ済みの変更量:
!`git diff --staged --stat 2>&1 || true`

ステージ済みの差分（先頭400行まで）:
!`git diff --staged 2>&1 | head -n 400 || true`

直近のコミット（書き方を合わせる参考）:
!`git log --oneline -10 2>&1 || true`

ユーザーからの補足: $ARGUMENTS

## 手順

1. **前提の確認**
   - gitリポジトリでない → その旨を伝えて終了
   - ステージ済みの変更がない → 「先に `git add` が必要」と伝え、未ステージの変更があれば何をステージすべきかの案を示して終了
   - 差分が400行で切れている → 必要なファイルだけ `git diff --staged -- <path>` で追加で読む
2. **目的が1つか確認する**
   - 無関係な変更が混ざっていたら、分割案（どのファイルをどのコミットにするか）を先に示す
3. **秘密情報の確認**
   - `.env`、鍵、トークン、パスワードらしきものが差分にあれば、最初に警告する
4. **メッセージを作る**（下のルールに従う）

## 書き方のルール

- **言語**: 日本語。ただし直近のコミットが英語中心ならそれに合わせる
- **接頭辞**: 直近のコミットが `feat:` `fix:` などを使っていれば合わせる。使っていなければ付けない
- **件名**（1行目）
  - 35文字程度まで（英語なら50文字まで）
  - 「何をしたか」を具体的に書く。末尾に句点を付けない
  - 「修正」「更新」「対応」「いろいろ」だけの件名にしない（何を・どう、まで書く）
- **本文**（件名の後に空行を1つ）
  - 「なぜ変えたか」を中心に書く。何を変えたかはコードを見れば分かる
  - 必要に応じて、影響範囲・注意点・関連するissueを書く
  - 1行は72文字（日本語なら40文字程度）で折り返す
  - 変更が自明なら本文なしでよい
- 差分に書かれていない理由を推測で書かない。理由が分からなければ、本文に `（理由を追記）` と置き、ユーザーに確認する

## 出力の形

```
<秘密情報の警告や分割案があれば、ここに最初に書く>

---
<件名>

<本文>
---

使う場合:
git commit -F - <<'EOF'
<件名>

<本文>
EOF
```

- 提案は1つだけ。別案は出さない
- 最後に「修正したい点があれば言ってください」と1行添える
